# 震线 EEW · 中日地震预警监视台

一个本地运行的地震预警（EEW）监视台：同时接入**日本**与**中国**的预警与速报数据，
在地图上做波前传播、台站到达时间与震度/烈度解算，用于观测、研究与教学。

> ⚠️ 非官方、非护命用途。数据来自公开镜像，存在延迟与丢失；请以日本气象厅、中国地震预警网等官方渠道为准。

## 运行

### 桌面版（推荐）

双击 `震线EEW.exe`：**内嵌 WebView2 窗口**，不启动外部浏览器，也不依赖用户装浏览器。
关闭窗口后本地服务一起退出。

自己打包：

```bat
build_exe.cmd
```

产物 `dist\震线EEW.exe`（单文件，约 21 MB，含 18 段标注语音与图标）。打包用的是 PyInstaller +
pywebview，第一次需要联网装这两个包（脚本已配好阿里云镜像）。

### 浏览器版

双击 `run.cmd`，或：

```bash
python server.py            # 默认 http://127.0.0.1:8765/
python server.py --port 9000 --no-browser
```

零依赖：只用 Python 标准库（3.9+）。浏览器打开后会自动重连，无需刷新。

### 可选：部署到公网

**当前默认形态是本机运行**，不依赖任何云平台。仓库里保留了 `render.yaml` / `Dockerfile` /
`Procfile` 与 `requirements.txt`，将来想把服务放到公网上，拿来就能用。

需要先明白一件事：**GitHub Pages 这类静态托管放不了这套东西**。服务端要持续轮询 18 个数据源、
维持 SSE 长连接、代理各家的无 CORS 接口，必须是常驻进程。

Render / Railway 这类平台的现状（2026-11 实测）：

- Render 免费档要绑外币卡，0.1 CPU / 512 MB，15 分钟无访问休眠，冷启动 30~60 秒
- Railway 是 $5 试用额度、30 天、不需要卡，但对「受限试用」账号可能限制出网
- Koyeb 免费档已在 2026-02 取消

真要部署，步骤是这样：

1. 平台用 GitHub 账号登录，授权访问本仓库
2. Render 走 **New → Blueprint**（自动读 `render.yaml`）；Railway 走 **Deploy from GitHub repo**
3. 启动命令：`python server.py --host 0.0.0.0 --port $PORT --no-browser`
4. 环境变量填 `EEW_INVITE`（邀请码），自己随便定一个字符串
5. 在 Networking 里 Generate Domain，拿到网址后用邀请码注册第一个账号
6. 部署完在平台控制台跑一次 `python -c "import auth; auth.init('data/users.db'); auth.create('你的账号','你的密码',True)"` 建出所有者账号（环境变量 `EEW_OWNER` 默认 `eggy`，不一致就两个都改成同一个名字）

注意事项：

- 免费实例 **15 分钟无访问会休眠**，冷启动期间收不到预警
- 免费实例的磁盘是临时的，重启后 `data/archive.json` 会清空，统计面板从零开始
- `data/tokens.json` 里的第三方令牌不会随仓库上传，云端这份是空的
- 公网暴露后**务必保留邀请码**，否则任何人都能注册；账号管理只属于所有者账号（`EEW_OWNER`，默认 `eggy`），这个用户名别人注册不了

## 多账号与数据源密钥

账号体系是每账号独立的：界面设置、关注点、图层各存各的（`data/users/<账号>/settings.json`），
同一个账号可以在多台设备同时登录，互不顶号。

**密钥分两类，严格分开，绝不互相借用：**

| 类型 | 存在哪 | 说明 |
| --- | --- | --- |
| 机器级令牌 | `data/tokens.json` | trem / eqsc / seedlink —— 抓的是「谁跑都一样的公开数据」，属于这台机器，改一次全机生效 |
| 账号级密钥 | `data/users/<账号>/tokens.json` | jian —— 个人授权，只属于这个账号 |

18 个数据源里只有 **Jian 预警流**需要个人密钥。它的规则是「跟着账号走」：

- 同一账号在手机、电脑上登录，用的是同一把密钥；在任一设备改，全端立刻生效；
- **换一个账号登录，用的就是那个账号自己的密钥**——不会沿用上一个账号的，
  也不会借用这台机器上曾经配过的那把；
- 没配密钥的账号就是没有 Jian 那一路（面板显示「待授权」），其余 17 个公开源照常；
- 每个账号的预警状态、演练、演练倍速都是独立的，甲调成 3× 不会把乙的演练加速。

> v1.13 及更早的版本把 jian 放在机器级 `data/tokens.json` 里共用，会出现
> 「换了账号却还是用上一个账号的密钥」。v1.14 启动时会自动把那份 jian 分发成
> 每个已有账号各一份（各改各的），并从机器级文件里删掉，之后新建的账号不再继承。

在「设置 → 数据源 → 我的 Jian 密钥」里填 / 换 / 清，保存后立刻生效，不用重启。
密钥只保存，界面永远不回显原文（只显示前 6 位 + 后 4 位），管理员也一样看不到。

**人员管理（站点所有者）**

v1.16 起改成**所有者模式**：账号管理只属于一个账号（默认 `eggy`，可用环境变量
`EEW_OWNER` 换人），其余账号都是普通账号——只能管自己的 Jian 密钥，看不到别人
的名字、设备和密钥，连「有哪些账号」都查不到（接口直接 403，不做任何枚举）。
`eggy` 这个名字也成了保留名，别人注册不了。所有者账号不能删除、不能强制下线；
新注册 / 新建号的都一律是普通账号，不再有「设为管理员」。

所有者在「设置 → 数据源 → 账号与密钥总览 → 打开管理」里，一个页面管三件事：

- **人**：建号（不受「关闭注册」与邀请码限制）、改密码（改完该账号全部设备被下线）、
  踢下线、删号（连同专属密钥与数据目录一起清干净）；
- **设备**：每个账号下面列出所有在线设备（什么设备、哪个 IP、最近活跃时间），
  可以单独让某一台下线，也可以一键全下；在哪台设备上打开这个面板都一样管用；
- **密钥**：替任意账号配 / 换 / 清 Jian 个人密钥。

**普通账号能管什么（v1.17）**：在「设置 → 数据源」里，
- 「我的 Jian 密钥」是**账号级私有**的，只有本账号用；
- 「本机公开数据源令牌」（trem / eqsc / seedlink）是**机器级共享**的，任何登录账号
  都能补全 / 替换 / 清除——这三路抓的是公开数据，一台机器只跑一份连接，
  改动对本机所有账号立刻生效（控制台会留一条 `[tokens] 谁改了什么` 的日志）。
  所以普通账号也能把「待授权」的那两路（EQSC、SeedLink）自己补上，
  不用麻烦所有者。SeedLink 填 `host:port`；Jian 密钥想写进这里会被拒绝
  （那是账号级的东西，只能填「我的 Jian 密钥」）。

## 震度速報闪现卡（v1.18 / v1.18.1）

**只有气象厅发的报才会弹这张卡**（v1.18.1）：日本的 EEW 速报、震度速報 /
震源・震度电文都是 `jma_*` 官报；中国地震台网、台湾 CWA、全球台网的速报
不套这张卡——那边没有「震度速報」这回事。气象厅没发，卡就不出现。

**卡片底色跟着报文里的震度走**（v1.18.1）：用的是气象厅震度分布图那套
标准配色——1 近白、2 蓝、3 深蓝、4 米黄、5弱 黄、5強 橙、6弱 红、
6強 暗红、7 紫；深底自动转白字，浅底黑字。认不出震度时回落黄底。

新地震的第一报会从屏幕顶上弹下这张卡，亮 12 秒自动收起、
点一下也能收：左边是最大震度大数字，右边是「震源 ×××」和发震时刻（×× 発生），
底部黑色条写震源 / 规模 / 深度——**还没查明的项就写「調査中」**，和气象厅
推特上那种官方卡一个样。同一场地震只闪一次（EEW 速报和随后的震度速報电文
算同一场），演练、推算、取消报不闪；迟到 90 秒以上的旧报也不补闪。

密钥原文任何人都看不到（含所有者），只显示前 6 位 + 后 4 位。
保护措施：不能删自己、不能删 / 踢所有者账号、不能踢自己正在用的这台设备、
删除账号需要点两次确认。

## 数据源

| 数据源 | 覆盖 | 内容 | 轮询 |
| --- | --- | --- | --- |
| 気象庁 緊急地震速報 | 日本 | 震源、M、深さ、最大予測震度、警報/予報、第 N 報、取消 | 1.2s |
| 中国地震预警（ICL） | 中国 | 震源、M、深度、最大烈度、报数 | 1.2s |
| 気象庁 震源・震度情報 | 日本 | 速報一覧（震度・津波コメント） | 20s |
| 中国地震台网 CENC | 中国 | 正式测定目录（含震中烈度） | 20s |
| 気象庁 震度観測点 | 日本 | 实测震度（震度速報 / 詳細震度，按市区町村 → 都道府县聚合） | 30s |

五个源各自线程轮询，互不影响；单源失败只让顶栏对应状态点变红，并保留上次数据，
不会让整个界面停摆。上游偶发连接重置（实测约 10% 请求），代码里做了空响应/截断 JSON 的容错。
「设置 → 数据源」里有这张表的实时版本（提供方 / 轮询周期 / 延迟 / 失败）。

> 中国目前**没有**公开的台站级实测震度接口，CENC 只给震中最大烈度，
> 所以中国台站只能显示推算值；日本有气象厅震度观测点，可以显示实测。

## 语音包

`web/sounds/voice/` 里是 **18 段已标注语义**的语音（来自用户导入的 EQuake 语音包）。
原始包里有 93 个文件，其中一部分只有数字文件名、没有标注——**这些一律不加载、不播放**。

| 组 | 内容 |
| --- | --- |
| 事件 | JMA 取消 / 地震发生 / 更新报 / 最终报 |
| 预想震度 | 预想最大震度 2 / 3 / 4 / 5弱 |
| 测站震度 | 震度 0（检测到测站反应）/ 1 / 2 / 3 / 4 / 5弱 / 5強 / 6弱 / 6強 / 7 |

同一段语义往往有 **人声版和提示音版** 两个文件（如 `exp5m.wav` / `exp5m-v.wav`）。
设置 → 语音包 → 「人声发音」开关：开 = 优先播人声版（没有人声版的段自动退回提示音版）；关 = 只播提示音版。

**声音调度（多通道，可并行）**：

| 通道 | 内容 | 规则 |
| --- | --- | --- |
| `evt` | 警报音 + 事件播报 | 通道内严格顺序（警报音 → 地震发生 → 预想震度）；新消息替换还没播的同 tag 消息 |
| `st` | 测站震度（S 波到达） | **不等不排队**，来了就播，新的顶掉旧的；可以和事件语音同时响 |
| `prev` | 设置里试听 | 先停掉所有通道再播 |

- **不重复**：同一段语音（同一 tag + 同一组文件）1.5 秒内只播一次，前端和后端各拦一道。
  桌面窗口和浏览器标签同时开着，也不会叠着念两遍。
- **警报音每场地震只响一次**；只有「影响我这里」的震度真的升了一档才再响。
- **测站语音中日都播**：不论日本还是中国大陆事件，只要有台站被 S 波扫到就报一次。
  只报「比之前更强」的档位（震度 4 之后不会再回头喊震度 3），同一档只报一次。
- **不怕被念白盖住**：台站语音响的时候，事件语音音量自动压到 32%，播完恢复。
- 最终报之后测站震度继续播（波还在传），可在设置 → 语音包里关掉；「取消」立即静音。
- 桌面版用 Windows MCI 多路播放，两个通道是真正的两层声音；浏览器版用多个 `<audio>`。
- 预想震度变了才重念；没变的续报每 7 秒最多一句「更新报」；取消只念一次。
- **语音包里没有这一档震度就直接不播**，绝不拿「更新报」冒充（以前会出现"跳错语音包"）。
  目前素材只有预想震度 2 / 3 / 4 / 5弱，5強以上只会播「地震发生」。
- 日本事件有语音包时不再叠系统 TTS（避免中日文两路一起念）。
- 「测站震度语音」可以单独关掉（大地震台站多时会安静不少）。

调试用：`GET /api/sound/log` 会返回最近 80 条播放记录（`play` / `skip-dup` / `fail`），
`GET /api/health` 里的 `engine` 说明当前走的是 `mci` 还是 `winsound`。

## 真实观测点怎么上图的

气象厅的震度速报（P2PQuake 中继 JMXSEIS）里**只有观测点地点名，没有经纬度**
（比如「球磨村渡」= 球磨村 + 観測点「渡」）。程序的处理：

1. 服务端收到速报后，把每个观测点交给 `pointgeo.py` 反查坐标：
   先按「去掉郡名的市町村名」最长前缀匹配（球磨村 → 球磨郡球磨村），
   再用剩下的地点名在该市町村的町丁目表里匹配（渡 → 32.240, 130.692）。
2. 结果缓存在 `data/point_geo.json`，命中过的地点不再联网；
   数据来自 HeartRails Geo API，精度为町丁目级（几公里内）。
3. 前端把这些观测点画成**小菱形**（和内置台站的圆点区分），颜色按实测震度；
   放大 3 倍以上时显示「地点名 + 震度」标签。
4. 收到新的震度速报时，按最高实测震度播一次「震度 N」语音——
   没有紧急地震速报的日本地震也一样有声音。

没有紧急地震速报、只有震度速报的日本地震，以前地图上什么都看不到，现在能看到
真实的观测点分布；语音也会报实测震度。

## 台站从哪来## 台站从哪来

| 层 | 来源 | 数据 |
| --- | --- | --- |
| 点位坐标 | `stations.py` 内置 192 个城市代表点（另支持 CSV 导入） | 城市中心的经纬度，**不是**官方台站精确位置 |
| 颜色（实测） | 气象厅震度观测点（P2PQuake 中继 JMXSEIS 电文） | 每个观测点的震度 → 按都道府县取最大 → 落到该县所有代表点 |
| 颜色（预计） | 本机衰减式计算 | 司・翠川(1999) PGV → 計測震度 / 中国烈度 |

气象厅的震度电文只有市区町村名、没有经纬度，所以做不到「一个点一个点」的落位；
按都道府县聚合是公开数据能做到的最细粒度。中国台站在观测模式下画成空心圈，表示「无公开观测」。

## 界面

地图优先的极简布局：整块地图铺满窗口，所有信息以悬浮层呈现，没有侧边栏。

- **顶部悬浮栏**：品牌 + 四个数据源的状态点（悬停看延迟/错误）、北京时间 / 日本时间、`历史`、声音、设置。
- **左上事件卡**（有事件时出现）：地名、M、深度、发震时刻，两个大数字——关注点的预计震度与主要动倒计时，
  底部一条 P/S 波进度。达到阈值时整卡转为深红渐变；历史回看为蓝色调。
- **左下「最近地震」**：中日最新速报 14 条，点击即在地图上定位（点「全部」打开历史抽屉）。
- **右侧工具条**：放大 / 缩小 / 复位 / 图层 / 全屏。
  - 图层面板：台站、烈度场、波前、地名 —— **台站点默认显示**（只在地图上打点，不再有列表）。
  - 台站着色：`自动 / 预计 / 观测`。自动 = 有进行中的预警看预计震度，空闲时看最近一次实测震度。
  - **台站按波前分三段**：P 波未到 = 暗点；P 到、S 未到 = 空心蓝圈；S 到 = 按震度上色。
    图例下方会写 `已反应 24/192`。
- **右下图例**：震度 0–7（含 5弱/5強/6弱/6強），下面一行写明当前台站着色依据
  （`台站实测 種子島近海 M4.0 · 最大1 · 4点 · 6.1h前` 或 `台站 · 预计震度`）。
- **历史抽屉**：底部上滑面板，24 小时 ~ 1 年、按震级过滤，点条目还原震中 / 烈度场 / 台站解算，并可回放波前。
- **设置**：关注点（预设城市 / 搜索 / 经纬度）、声音与语音、告警阈值、台站 CSV 导入、演练。

交互：拖拽平移、滚轮缩放、**单击地图任意位置设为关注点**（点到台站附近会吸附到该台站）。
快捷键：`M` 声音、`S` 设置、`F` 全屏、`R` 复位、`H` 历史、`空格` 回放波前。

## 予想震度：优先用气象厅的

日本气象厅的紧急地震速报里带 `WarnArea`（地域别予想震度）。有这块数据时：

1. `sources.parse_pref_areas()` 把「宮城県北部 / 5弱」这类地域压成「都道府県 → 最大予想震度」；
2. 地图直接按都道府县填色，县中心标数字，台站点也按所属县取同一个值；
3. 本机不再做任何外推。

只有在 `WarnArea` 为空（予報、または震度1程度）时，才退回 6px 网格的衰减式估算，
图例会写清楚当前用的是哪一种：`气象厅 予想震度（都道府県）` / `台站 · 预计震度（推算）`。

## 烈度场

地图上的烈度不是渐变糊，而是按约 6px 一格逐格计算再直接铺上去的**网格区块**，
每一格用同一套衰减式算 PGV → 震度/烈度，所以边界是台阶状的，和 JMA 的震度分布图一个逻辑。
格子在缩放时保持屏幕像素大小，放大后相当于更细的网格。

## 历史回看

两个来源合并、按时间倒序、去重（150 km / 180 s 内视为同一次）：

| 来源 | 覆盖 | 说明 |
| --- | --- | --- |
| 本地归档 `data/archive.json` | 中日 | 运行时把 CENC / JMA 速报持续写入，重启不丢，中文/日文地名 |
| USGS FDSN | 全球 M4.5+ | 按日期区间查询，补齐本地没有的历史；英文地名自动加中文国别 |

本地归档最多保留 4000 条；USGS 结果缓存 15 分钟，避免重复请求。

## 台站

内置 **192 个中日代表点**（日本 97 个市域点，中国 95 个省会/重点震区/台湾地区城市），
只作为地图点位显示，不占界面；可以用图层开关关掉，
坐标取城市中心，用于到达时间与烈度的**估算**，不是官方台站的精确坐标。

要接入真实台站网络（JMA 震度観測点、K-NET/KiK-net、各省预警台站），在
`设置 → 台站 → 导入台站` 粘贴 CSV，每行：

```
code,name,country,lat,lon[,net]
KNET.TKYH,東京平河町,JP,35.690,139.692,K-NET
SC.51001,成都,CN,30.572,104.066,四川预警
```

导入后立刻参与地图打点、排序与到达解算，保存在 `data/custom_stations.json`。

## 算法

- 震中距：Haversine；震源距 `R = √(D_epi² + depth²)`
- 走时：**双层水平地壳模型**（界面深度 H = 30 km，Vp 6.00 / 6.90 km/s，Vs 3.47 / 3.99 km/s）。
  直达波 `t = √(Δ²+h²)/v1`；首波（折射）`t = (2H−h)/(v1·cosθc) + (Δ−(2H−h)·tanθc)/v2`，`sinθc = v1/v2`；
  两者取早到分支。波前半径用反解 `Δ(t)`，所以远场会比近场跑得快一点，而不是匀速直线扩张。
- 峰值速度：司・翠川(1999) `log10(PGV) = 0.58M + 0.0038D − 1.29 − log10(R) − 0.002R`（cm/s）
- 日本震度：計測震度 `I = 2.68 + 1.72·log10(PGV)`，再按 JMA 档位（5弱/5強/6弱/6強）分级
- 中国烈度：按 GB/T 17742 峰值速度分档插值，Ⅵ 度 ≈ 0.06 m/s，每度约翻倍
- 波前：Mercator 保角，`px/km = s / (R_earth·cosφ)`，所以等距圆在图上仍是圆
- 事件卡点「公式」会展开当次计算的中间量：Δ、h、Vp/Vs、直达/首波走时、最终取哪一支

衰减式没有考虑场地放大、方位性与深部结构，**误差可达 ±1 个等级**，仅作量级参考。

## 已知边界

- 中国预警（ICL）接口在无事件时会长时间保留上一条记录，因此界面用「发震时刻 5 分钟内」判定有效，
  过期事件只出现在「预警流水」，不会触发告警。
- 日本 EEW 的「予報/警報」以 `isWarn` 区分；`isTraining`（訓練）事件不响铃，仅显示。
- 上游为第三方镜像，不保证服务水平；生产用途请直连 JMA XML feed 与国家级预警接口。
- 地图未做投影裁剪，缩放很大时海岸线会显示 0.01° 的折线感。
- 烈度场是各向同性的衰减估算，不会出现真实震度分布里的方位性、盆地放大等细节。
